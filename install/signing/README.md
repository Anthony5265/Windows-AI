# Windows AI Code Signing Infrastructure

This directory contains scripts and configuration for digitally signing the Windows AI installer with Authenticode certificates.

## Overview

Code signing provides several critical benefits:

1. **User Trust** - Signed installers display publisher information and don't show "Unknown Publisher" warnings
2. **SmartScreen Reputation** - EV certificates provide immediate SmartScreen reputation; OV certificates build reputation over time
3. **Integrity Verification** - Users can verify the installer hasn't been tampered with
4. **Professional Distribution** - Essential for enterprise deployment and public releases

## Quick Start

### Development / Testing

```powershell
# 1. Generate test certificate (one-time setup)
.\create-test-cert.ps1

# 2. Sign installer with test certificate
.\sign-installer.ps1 -InstallerPath "..\WindowsAI-Setup-0.5.0.exe" -UseTestCert
```

### Production

```powershell
# Sign with production certificate
.\sign-installer.ps1 -InstallerPath "..\WindowsAI-Setup-0.5.0.exe" `
                     -CertificatePath "C:\Certificates\windows-ai-prod.pfx" `
                     -CertificatePassword "YourSecurePassword"
```

## Detailed Usage

### Creating Test Certificates

For development and testing only:

```powershell
# Basic usage - creates test-cert.pfx
.\create-test-cert.ps1

# Custom subject and password
.\create-test-cert.ps1 -SubjectName "CN=My Company Test" -Password "mypassword"

# Install to Trusted Root (removes security warnings)
.\create-test-cert.ps1 -InstallToStore

# Custom validity period
.\create-test-cert.ps1 -ValidYears 3
```

**Important Notes:**
- Test certificates are self-signed and will show security warnings to users
- Installing to Trusted Root requires Administrator privileges
- Test certificates are suitable for development/internal testing only
- **Never distribute installers signed with test certificates to end users**

### Signing Installers

#### Option 1: Use Test Certificate

```powershell
.\sign-installer.ps1 -InstallerPath "path\to\WindowsAI-Setup-0.5.0.exe" -UseTestCert
```

#### Option 2: Use Specified Certificate

```powershell
.\sign-installer.ps1 -InstallerPath "path\to\WindowsAI-Setup-0.5.0.exe" `
                     -CertificatePath "C:\Certificates\my-cert.pfx" `
                     -CertificatePassword "SecurePassword123"
```

#### Option 3: Use Configuration File

Edit `sign-config.json`:
```json
{
  "certificatePath": "C:\\Certificates\\windows-ai.pfx",
  "certificatePassword": "YourPassword",
  "timestampServer": "http://timestamp.digicert.com"
}
```

Then run:
```powershell
.\sign-installer.ps1 -InstallerPath "path\to\WindowsAI-Setup-0.5.0.exe"
```

#### Option 4: Use Certificate from Windows Certificate Store

If certificate is installed in Windows Certificate Store:
```powershell
.\sign-installer.ps1 -InstallerPath "path\to\WindowsAI-Setup-0.5.0.exe"
```

The script will automatically find and use the first available code signing certificate.

### Advanced Options

```powershell
# Use custom timestamp server
.\sign-installer.ps1 -InstallerPath "..." -TimestampServer "http://timestamp.sectigo.com"

# Skip signature verification
.\sign-installer.ps1 -InstallerPath "..." -Verify:$false

# Use specific config file
.\sign-installer.ps1 -InstallerPath "..." -ConfigFile "custom-config.json"
```

## Obtaining a Production Certificate

### Certificate Types

#### Organization Validation (OV) Certificate
- **Cost**: $100-$400/year
- **Validation**: Organization identity verified
- **Reputation**: Builds over time (can take weeks/months)
- **Best for**: Most software publishers

#### Extended Validation (EV) Certificate
- **Cost**: $300-$600/year
- **Validation**: Extensive organization vetting
- **Reputation**: Immediate SmartScreen reputation
- **Hardware**: Requires USB token or HSM
- **Best for**: Large-scale distribution, enterprise software

### Recommended Certificate Authorities

1. **DigiCert** (Recommended)
   - URL: https://www.digicert.com/code-signing
   - Industry leader with excellent reputation
   - Good support and documentation
   - Pricing: ~$400/year (OV), ~$500/year (EV)

2. **Sectigo (formerly Comodo)**
   - URL: https://sectigo.com/ssl-certificates-tls/code-signing
   - Good value, widely trusted
   - Pricing: ~$200/year (OV), ~$400/year (EV)

3. **GlobalSign**
   - URL: https://www.globalsign.com/en/code-signing-certificate
   - Strong reputation, global presence
   - Pricing: ~$300/year (OV), ~$500/year (EV)

4. **Certum**
   - URL: https://en.sklep.certum.pl/
   - Budget option, still trusted
   - Pricing: ~$100/year (OV)

### Procurement Process

1. **Choose Certificate Type** - OV or EV based on needs and budget
2. **Select Certificate Authority** - From list above or research others
3. **Purchase Certificate** - Complete order on CA website
4. **Validation Process**
   - Submit organization documents
   - Verify business registration
   - Phone verification
   - For EV: More extensive vetting (can take 1-2 weeks)
5. **Receive Certificate**
   - Download certificate file (.pfx or .p12)
   - Secure password will be provided
   - For EV: Certificate loaded onto USB token
6. **Store Securely** - See "Security Best Practices" below

### Timeline
- **OV Certificate**: 1-5 business days for validation
- **EV Certificate**: 1-2 weeks for validation

## Security Best Practices

### Certificate Storage

**DO:**
- Store certificates in secure, encrypted locations
- Use strong passwords (16+ characters, random)
- Limit access to certificates (need-to-know basis)
- Keep certificates out of version control
- Use environment variables for passwords in scripts

**DON'T:**
- Commit certificates to Git repositories
- Store passwords in plain text
- Share certificates via email/chat
- Use weak passwords like "password123"
- Store certificates on publicly accessible servers

### For CI/CD Pipelines

1. **GitHub Actions**
   ```yaml
   # Store certificate as base64-encoded secret
   - name: Decode certificate
     run: |
       $cert = [Convert]::FromBase64String('${{ secrets.SIGNING_CERT }}')
       [IO.File]::WriteAllBytes('cert.pfx', $cert)

   - name: Sign installer
     run: |
       .\install\signing\sign-installer.ps1 `
         -InstallerPath "dist\WindowsAI-Setup.exe" `
         -CertificatePath "cert.pfx" `
         -CertificatePassword "${{ secrets.CERT_PASSWORD }}"

   - name: Clean up
     run: Remove-Item cert.pfx -Force
   ```

2. **Azure Key Vault**
   - Store certificates in Azure Key Vault
   - Use Azure SignTool or Key Vault integration
   - Provides audit logging and access control

3. **AWS Certificate Manager / KMS**
   - Store certificates in AWS Secrets Manager
   - Use IAM roles for access control
   - Integrate with CodeBuild/CodePipeline

### Password Management

Instead of hardcoding passwords:

```powershell
# Option 1: Environment variable
$env:CERT_PASSWORD = "YourPassword"
.\sign-installer.ps1 -InstallerPath "..." -CertificatePassword $env:CERT_PASSWORD

# Option 2: Secure string file
$password = Get-Content "secure-password.txt" | ConvertTo-SecureString
.\sign-installer.ps1 -InstallerPath "..." -CertificatePassword $password

# Option 3: Interactive prompt (for local development)
.\sign-installer.ps1 -InstallerPath "..." -CertificatePath "cert.pfx"
# Script will prompt for password
```

## Timestamp Servers

Timestamp servers are critical for long-term signature validity. They ensure signatures remain valid even after the signing certificate expires.

### Configured Timestamp Servers

In `sign-config.json`:
- **DigiCert**: `http://timestamp.digicert.com` (Primary, most reliable)
- **Sectigo**: `http://timestamp.sectigo.com`
- **GlobalSign**: `http://timestamp.globalsign.com/tsa/r6advanced1`
- **Certum**: `http://time.certum.pl`

### Fallback Strategy

If signing fails due to timestamp server issues:

```powershell
# Try different timestamp server
.\sign-installer.ps1 -InstallerPath "..." -TimestampServer "http://timestamp.sectigo.com"
```

## Integration with Build Process

### Manual Integration

Update `build-installer.ps1`:

```powershell
# Add at the end of Step 6: Build NSIS Installer
if ($LASTEXITCODE -eq 0) {
    Write-Host "  Signing installer..." -ForegroundColor Gray

    # Sign installer
    & "$PSScriptRoot\signing\sign-installer.ps1" `
        -InstallerPath "$OutputDir\$installerFile" `
        -UseTestCert  # Or use production cert

    if ($LASTEXITCODE -ne 0) {
        Write-Host "  WARNING: Signing failed" -ForegroundColor Yellow
    }
}
```

### Automated CI/CD

See `.github/workflows/build-installer.yml` for automated signing in GitHub Actions.

## Troubleshooting

### SignTool Not Found

**Error:** `SignTool not found`

**Solution:**
1. Install Windows SDK: https://developer.microsoft.com/en-us/windows/downloads/windows-sdk/
2. During installation, select "Windows SDK Signing Tools for Desktop Apps"
3. Verify installation: `Get-ChildItem "C:\Program Files (x86)\Windows Kits\*\bin\*\signtool.exe"`

### Certificate Not Found

**Error:** `Certificate not found`

**Solutions:**
- Verify certificate path is correct
- Check certificate password
- Ensure certificate file has `.pfx` or `.p12` extension
- For test certificates, run `create-test-cert.ps1` first

### Timestamp Server Failure

**Error:** `The specified timestamp server either could not be reached or returned an invalid response`

**Solutions:**
1. Check internet connectivity
2. Try different timestamp server:
   ```powershell
   .\sign-installer.ps1 -InstallerPath "..." -TimestampServer "http://timestamp.sectigo.com"
   ```
3. Wait and retry (timestamp servers can be temporarily unavailable)
4. Check corporate firewall rules

### Signature Verification Fails

**Error:** `Signature verification failed`

**For Test Certificates:**
- This is expected for test certificates
- Install test certificate to Trusted Root: `.\create-test-cert.ps1 -InstallToStore`

**For Production Certificates:**
- Verify certificate is from trusted CA
- Check certificate is not expired
- Ensure certificate chain is complete
- Verify timestamp server was used

### Access Denied

**Error:** `Access denied` or permission errors

**Solutions:**
- Run PowerShell as Administrator
- Check file permissions on certificate and installer
- Ensure certificate file is not locked by another process

## Verification

### Verify Signed Installer

```powershell
# Using signtool
signtool verify /pa /v "WindowsAI-Setup-0.5.0.exe"

# Using PowerShell
Get-AuthenticodeSignature "WindowsAI-Setup-0.5.0.exe"

# Check signature details
Get-AuthenticodeSignature "WindowsAI-Setup-0.5.0.exe" | Format-List *
```

### What Users See

**Signed with Valid Certificate:**
- Publisher name displayed
- No security warnings
- SmartScreen allows installation (after reputation built)

**Signed with Test Certificate:**
- "Unknown Publisher" warning
- SmartScreen may block
- Users must click "More info" → "Run anyway"

**Unsigned:**
- "Unknown Publisher" warning
- SmartScreen blocks
- Users must disable SmartScreen or use elevated permissions
